推理为什么贵：
量化、缓存与注意力

用户发出一条消息，等了半秒才看到第一个字，之后每个字又花几十毫秒。账单上的成本与用户感受到的等待，来自同一套计算，却由不同的资源决定。显存（GPU Memory）、带宽（Bandwidth）与算力这三样东西，在不同阶段轮流成为瓶颈。

打个比方，跑模型像开长途货车。算力是发动机马力，带宽是公路能跑多快，显存是货斗能装多少。装得多不多、跑得快不快，卡在哪个环节，要分阶段看。

正式定义：推理（Inference）指用已经训练（Training）好的模型处理输入、算出输出的过程。它和第 20 章讲的推导能力（Reasoning，组织中间步骤解题）不是一回事。

速览

推理要同时满足质量、延迟与成本三个目标。预填充（Prefill）通常吃算力，小批量解码（Decoding）吃带宽；先判断瓶颈在哪，再选优化。键值缓存（Key-Value Cache）用显存换算力，量化（Quantization）用精度换字节，分组查询注意力（Attention）用更少的键值头换更小的缓存。每种优化省的是不同资源，要按瓶颈选择。

为什么读完很久，输出又慢慢出现

一次请求的等待可以分成读入材料和逐步生成。预填充先处理已有输入，解码再继续产生 词元（Token）。两段的计算形状不同，服务端的瓶颈也可能不同。

可以想象小模先读档案，再写回答。这个比喻只帮助区分两个阶段：系统能并行处理输入中的许多位置，自回归生成的后续 token 却依赖已经生成的内容。因此，等到第一个 token 和等到整段回答完成，是两种等待。

缓存省去了哪部分重算

生成新 token 时，一些前文计算结果可以保留下来，避免每轮都从头计算。键值缓存记录的是注意力用到的中间结果，需要占用显存。

假设两次调用共享完全相同的前缀，服务满足相应条件时还可能复用前缀处理。若每次把不断变化的时间戳插在最前面，稳定前缀就会缩短。这是组织输入可能影响成本的一种方式，具体行为仍取决于服务实现。

量化用较少位数表示部分数值，可以减少存储与带宽需求。它的效果取决于模型、硬件和任务。文件变小，延迟收益要看任务与硬件；质量变化也需要测量。

比较两项服务时，先让它们做同样的任务，并记下输入与输出长度、首 token 延迟、总时间和账单。只需一句答复的任务，和要写长文的任务，等待的主要部分可能不同。

把模型文件压到一半大小，回答时间未必减半。还要检查计算、带宽、缓存和并发等限制。

机制

两本账：公司成本与用户等待

公司视角算的是卡数乘租金与计费时长。显存决定能装下什么，吞吐决定一张卡能服务多少流量。用户视角算的是排队、预填充与逐 token 解码三段。

首字延迟（Time To First Token，TTFT）覆盖排队、预填充和第一个输出 token 的解码；每输出 token 耗时（Time Per Output Token，TPOT）衡量之后每一步。举例：同一请求在两张卡上跑，吞吐翻倍但排队变长，用户感知的 TTFT 反而更高。

延迟的三段能压，手段不同。排队靠调度与扩容，预填充靠算力与并行，解码靠带宽与缓存。

两本账要一起看。只优化吞吐，可能把延迟推高；只压延迟，卡就空着一半。举例：一张卡按每小时 2 美元算，一天 48 美元；日服务 3 万请求，单请求成本约 0.0016 美元（假设）。

预填充与解码是两种负载

预填充一次把整段提示并行送进模型，产出第一个 token。解码每步只喂上一个 token，重复到结束。

按 2·N·T 粗估，N=7B、T=4096 时，预填充约 2×7×10⁹×4096≈5.7×10¹³ 次浮点运算（57 万亿次）。逐层细算给 5.745×10¹³ 次，量级一致。单步解码只处理一个新 token，按 2·N 粗估约 14 GFLOPs；细算含读取历史的注意力，得 15.10 GFLOPs。

两者都要把权重读一遍。三个教学配置分开列：

图 21.1 先区分两段计算的职责：预填充处理已有输入，解码利用输入与已经生成的内容继续预测。上面的时间是特定配置下的教学下界；真实服务延迟还要加上排队与调度开销。

预填充的算力可以并行摊开，解码不行。解码每步只算一个 token，矩阵小，算力用不满，时间花在把权重从显存搬到片上。

这个结论只在小批量下成立。批量一大，权重读取被多个请求摊薄，解码会重新回到算力或缓存带宽的限制。

键值缓存用显存换算力

因果注意力有个关键性质：位置 t 只依赖前缀，前面的键和值不会变。历史键值可以存下来复用，这就是键值（Key-Value，KV）缓存。

缓存能复用，是因为权重、位置与前缀都不变，前面的键值就不会变。存一次、用多次，换的是延迟下降与吞吐上升。

缓存显存按层数、并发、长度、键值头数、头宽与精度字节相乘。举例：32 层、32 头、头宽 128、BF16。每个 token 每请求的缓存是 2×32×32×128×2=524,288 字节。换算过来是 512 KiB。

MKV=2×L×B×T×H×d×bM_{\text{KV}} = 2 \times L \times B \times T \times H \times d \times bMKV​=2×L×B×T×H×d×b

L 是层数，B 是并发批大小，T 是长度，H 是键值头数，d 是头宽，b 是每个元素占的字节数。开头的 2 表示键与值各一份。

4096 上下文（Context）时单请求 2 GiB，8 个并发请求就是 16 GiB。8192 上下文时单请求 4 GiB，8 并发 32 GiB，显存会先于算力成为上限。

图 21.2 固定模型配置，只改变长度与并发数。每格代表 2 GiB：长度从 4,096 增到 8,192，缓存由一格变成两格；八个这样的请求并发，共用掉 32 GiB。

权重量化省的是权重显存；缓存要另外量化，才会跟着缩小。

缓存换来的是更低的延迟，代价是显存。显存又限制并发与上下文长度，三者在容量规划里互相拉扯。

量化用精度换字节

量化把浮点映射到低位宽的整数网格：先除以步长，四舍五入，再加零点。反量化是先减零点，再乘回步长。对称量化没有零点偏移，步长由最大绝对值决定。

s=max⁡∣x∣2b−1−1,q=round⁡(xs),x^=s⋅qs = \frac{\max|x|}{2^{b-1}-1}, \qquad q = \operatorname{round}\left(\frac{x}{s}\right), \qquad \hat{x}=s \cdot qs=2b−1−1max∣x∣​,q=round(sx​),x^=s⋅q

s 是步长，b 是位宽，q 是整数网格上的取值，x̂ 是重建值。b=4 时，单侧有 7 个整数格。

举例：对称 4-bit 把范围 [-3.5,3.5] 映射到 [-7,7]，步长取 3.5/7=0.5，零点为 0。输入 1.3 时，1.3/0.5=2.6，四舍五入得 3，重建值 1.5，误差 0.2。

量化分两条路。训练后量化拿现成权重，用少量校准数据定步长；量化感知训练在前向模拟误差，让模型学着适应，成本更高。

只量化权重，算力不变，省的是显存与带宽；激活也量化，才可能用上更快的整数运算。

4-bit 的常见做法是分组。每 128 个权重共享一个步长，128 个值占 64 字节，加一个 FP16 步长 2 字节，开销只有 3.1%。

失败案例在异常值。一组普通权重在 [-0.4,0.3] 之间，混进一个 7.0，整组步长会被拉到 1.0。普通权重除以步长后接近 0，四舍五入全变成 0，这一组的信息就丢了。分组量化把这种影响限制在一组之内。

效果要看场景。一些公开对比里，7B 级模型在 INT4 量化后权重占用明显下降，吞吐也可能提升。具体倍数与质量损失随实现、校准集和测试设置变化。

累加精度是另一个坑。从 2048 开始连续加 1 四次，FP32 得到 2052；FP16 每步都舍回 2048，误差 4。求和、归一化（Normalization）与 softmax 要用高精度累加。

注意力变体共享键值头

多头注意力（Multi-Head Attention，MHA）给每个查询头配一套键值头。分组查询注意力（Grouped Query Attention，GQA）让多个查询头共享一组键值头；多查询注意力（Multi-Query Attention，MQA）只保留一组。

设 64 个查询头、头宽 128、上下文 4096、BF16，运算只含注意力子层；拿一个 80 层模型对比三种设计。缓存分别是 10 GiB、1.25 GiB 与 160 MiB。单层解码的浮点运算从 671.09 MF 降到 436.21 MF 与 406.85 MF。

查询头数不变，键值头数变少。查询仍按全部头算，缓存按共享后的头存，这就是运算降得少、缓存降得多的原因。

分组查询注意力把缓存缩到八分之一，解码注意力子层的浮点运算只少约 35%。前者衡量显存占用，后者衡量浮点运算次数（Floating Point Operations，FLOPs）。端到端（End-to-End）延迟还要看权重读取：解码要读全部权重，权重读取占大头，缓存变小的时间收益会被摊薄。要判断收益，得看缓存读取占总带宽的比例。

图 21.3 用4个查询头展示三种键值共享方式。它只解释共享关系；上面的容量算例使用另列的模型配置，图中的头数不参与计算。

训练阶段还要看模型容量。键值头数变少，模型容量可能受影响，质量是否下降取决于预训练与微调（Fine-Tuning），不能只看缓存数字。

服务端调度把卡用满

静态批处理要等整批请求全部结束才换下一批，短请求留下的槽位空转到长请求收尾。连续批处理（continuous batching）改成每生成一步就换人，谁结束就立刻补进新请求。

分块预填充（chunked prefill）把长提示切成小段，与正在解码的请求交错执行，避免一次长预填充把所有人卡住。前缀缓存（Prefix Cache）（prefix caching）复用相同提示前缀的缓存状态，省掉重复计算。

这些技术解决的是同一个问题：让一张卡同时服务更多请求，同时不让任何一个请求等太久。

推测解码（speculative decoding）是另一条路。小模型先草拟几个 token，大模型（Large Language Model）一次前向并行校验，接受匹配的前缀，丢掉第一个不匹配之后的部分。按接受-拒绝规则校验后，输出分布不变；延迟取决于草稿命中率，代价是多一份草稿模型的显存。

FlashAttention 把注意力拆成小块，在片上缓存里计算，用在线 softmax 合并中间结果；它省的是 HBM（高带宽显存）与片上缓存之间的搬运和完整 T×T 矩阵的峰值显存，不消除 T² 的运算量。第 19 章已展开，这里只记住它对长上下文显存的意义。

PagedAttention 把缓存切成固定大小的块，再用块表记录各段数据存在哪里。它借鉴操作系统的分页方式，使每个请求无需预留一整段连续显存。

真正的限制在实现复杂度。换调度器与内核要重测，收益随负载形状变化。

成本与限制

这些优化都有边界。键值缓存随长度线性增长，上下文 8192 时单请求 4 GiB，8 并发 32 GiB，显存会先于算力成为上限；量化有精度损失，损失多大取决于模型、校准集与任务，在客服对话里也许可接受，在代码与数学上可能放大（推断）；分组查询注意力的收益在带宽受限的解码上最明显，质量是否受影响取决于训练，不能只看缓存数字（推断）。

优化的顺序取决于瓶颈：先测预填充与解码的耗时占比，再决定加算力、加带宽还是加缓存。这些延迟与带宽数字是单张 A100、批大小为 1 的下界；KV 缓存容量例子另按 8 并发算，真实系统要重新测。

混合专家（Mixture of Experts，MoE）只减少激活计算：每层有很多专家，每个 token 只激活其中少数几个。全部专家权重仍要驻留显存，容量规划不能只按激活参数算。
