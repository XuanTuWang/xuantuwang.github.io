附录 E · 自测答案

答案只依据对应章节的正文；正文不足以回答的地方，在文末缺口清单里说明。

第 1 章 · Agent 是什么：模型加工具

  1. 模型负责决策，工具负责动作，运行时负责执行与收尾。模型没有数据库连接，也没有权限。
  2. 第 3 步必须由运行时代码完成。模型没有权限，代码负责校验参数、检查权限并真正执行查询。
  3. 查 C 房 14:00 时返回「14:30 已被占用」，这个观察让计划改查 D 房。没有可用房间时应停下来问用户。
  4. 期望损失是 0.005 × 20,000 × 100 = 10,000 元。人工确认 100 次共 3,000 秒，即 50 分钟。

第 2 章 · 一个请求如何变成一次行动

  1. 模型负责决策，输出一个具体的工具调用。软件负责执行，由运行时校验参数、限制权限并留下证据。两者不能互换，因为模型没有数据库连接和权限，而运行时看不到模型的意图。
  2. 「已处理 6 天」让模型判断需要核对政策。它调用 lookup_policy 查到「超过 5 天应升级」，于是请求用户授权升级。
  3. 运行时会校验参数格式，能拦住缺字段或类型不对的调用。它拦不住「格式对、订单不存在」的情况，处理函数只能返回 not_found。
  4. 输入是 4 × 3,000 = 12,000 tokens，按每百万 2 美元算为 0.024 美元。输出是 4 × 200 = 800 tokens，按每百万 10 美元算为 0.008 美元。合计约 0.032 美元。

第 3 章 · 一个 token 是怎么生成的

  1. 打分与采样这一段引入随机性。前面四段只做确定性计算，同一输入的结果固定。
  2. 切分粒度变粗，同一文本的 token 序列通常变短。嵌入矩阵从 [5 万, d] 变成 [10 万, d]，输出层同倍增长，显存不一定省。
  3. 温度大于 1 时分布更平，次高项的概率上升。采样从更平的分布里抽，两次抽到不同 token 的机会变大。
  4. 分数矩阵是 8,192 × 8,192 = 67,108,864 个元素，是 16 × 16 = 256 的 262,144 倍。宽度 128 时，四个投影合计 4 × 128² = 65,536 个参数。

第 4 章 · 上下文预算：一次推理里装什么

  1. 七项是指令、历史、当前请求、工具定义、证据、记忆与技能、生成预留。输出逐 token 生成，不先扣预留，回答会在中途被截断。
  2. 容量不足会报错或截断，现象是回答断在半句。相关性差会答得流畅但引用了别处证据。新鲜度差会用旧版本证据，答案流畅地错。
  3. 剩余 3,328 tokens 只够两段政策 3,200 tokens。第三段再占 1,600 就超出 1,472，只能从生成预留里扣，1,024 的预留会被击穿。
  4. 3,840 + 1,024 = 4,864，8,192 − 4,864 = 3,328 tokens。两段政策占 3,200 后，还剩 128 tokens。

第 5 章 · 上下文工程：压缩、刷新与前缀缓存

  1. 是「时机」这个决策。它决定哪些内容现在加载，哪些等工具结果回来再加载。
  2. 每轮都要重发历史，输入成本随轮次线性增长。五次调用累计 80,000 tokens，按每百万 2 美元是 0.16 美元。
  3. 命中条件是序列化后的 token 前缀逐字节相同。语义相近但字面不同的前缀字节不同，缓存命中不了。
  4. 不缓存是 50,000 × 2 ÷ 1,000,000 = 0.1000 美元。启用复用后未命中 18,000 tokens 是 0.036 美元，命中 32,000 按一成是 0.0064 美元。总成本 0.0424 美元，下降 57.6%。

第 6 章 · 工具：契约、约束解码与 MCP

  1. 三部分是名称、输入 schema 和执行结果。模型只看得到名称、描述与参数说明，看不到执行函数、数据库位置与权限。
  2. 四道依次拦 JSON 语法错、schema 与类型不符、动作不被允许、权限与前置条件不满足。
  3. schema 只保证字段齐全、类型对、模式匹配。它不知道 ORD-1002 是否存在、属于谁，也不验证动作资格。
  4. 定制适配要写 3 × 5 = 15 份。统一协议之后是 3 份服务端加 5 份客户端，共 8 份，省下 7 份。

第 7 章 · 工具调用循环与失败恢复

  1. 四个动作是组装上下文、模型决策、校验并执行、观察写回。三个停止条件是给出回复、需要用户输入、达到应用限制。
  2. 全部串行是 4 × 0.8 + 1.2 + 0.9 + 1.1 = 6.4 秒。三次读取并行、模型调用压到两次后是 2 × 0.8 + 1.2 = 2.8 秒。
  3. 超时不等于没执行，退款可能已经生效。安全重试要带稳定的操作标识符，并在重发前先查上一次的结果记录。
  4. 好处是长任务有更多合法步骤可用，不会被上限截断。风险是卡住的循环能烧掉更多调用与费用，需要配合时间上限与重试上限。

第 8 章 · 记忆：四种角色与作用范围

  1. 四种记忆的颗粒度不同。语义记客户偏好邮件联系这类事实，情景记十月一日重启无效这类事件。程序记先确认型号再查指南这类做法，工作记忆记当前目标与下一步。
  2. 单请求状态只活一次推理，跨对话偏好要长期保存。放错层会让临时让步变成长期规则，或让偏好随进程重启丢掉。
  3. 不按归属过滤时精度是 1/5，即 20%。按归属过滤后取前 3 条全部正确，精度是 100%。
  4. 两条记录都保留：旧的邮件偏好标为「已被替代」，新的电话偏好作为当前值。两条都要带修改时间与证据来源。

第 9 章 · RAG 与图记忆

  1. 建库段做收集解析、切块、编码并建索引。查询段做过滤、检索、重排、生成带来源的回答。过滤在前，因为版本与作用域决定哪些证据可用，检索只在这些证据里排序。
  2. P@5 是 2/5 = 0.4，R@5 是 2/4 = 0.5。第一条正确证据排第 2，倒数排名是 1/2 = 0.5。
  3. A 是 1/61 + 1/65 ≈ 0.0318。B 是 1/63 + 1/62 ≈ 0.0320，B 的分数更高。
  4. 适合关系密集、需要多跳的问题，例如这位客户买过哪些设备、维修记录里有没有重复故障。不适合只查一条记录的问题，例如某台设备保修几年。

第 10 章 · 技能包：结构、分阶段加载与自改进

  1. 入口说明决定什么时候用，引用材料提供细节，脚本做可重复校验，模板提供输出格式。脚本要单独测试，因为数据格式一改就会读错字段，技能在校验这一步失败。
  2. 全读是 40 × 500 = 20,000 tokens。只读目录加一个包是 1,200 + 500 = 1,700 tokens。
  3. 精确率是 20/25 = 80%，召回率是 20/30 ≈ 67%。这里召回偏低，该改描述的适用范围与关键词，让该触发时能选中。
  4. 不能直接采纳。20 个案例里一个就是 5 个百分点，多通过 2 个很可能只是波动，要冻结样本回测，并要求连续两轮提升或门槛高于 10 个百分点。

第 11 章 · 评估分层与 LLM 指标

  1. 四层是模型回答、工具执行、技能贡献、端到端任务。只报端到端分数，分不清是选错工具、填错参数，还是验收标准写错。
  2. 准确率是 90/100 = 0.90。负类召回是 0/10 = 0，那 10 条不该转的工单一条也没被识别，所以高分有欺骗性。
  3. 词重叠 F1 是 2/3 ≈ 0.667。它没算否定词与词序，「已经」替换「尚未」后结论相反，分数照样高。
  4. 通过率是 1 − C(7,3) ÷ C(10,3) = 1 − 35/120 ≈ 0.708。前提是能测试并挑选候选，不挑选时多次采样只是多花钱。

第 12 章 · 运行时控制器：预算、停止与验收回路

  1. 控制器拥有当前这次运行、预算与停止判定，编排器负责选阶段、路由与分配执行者。合并会让预算被业务分支绕过，轮次上限形同虚设。
  2. 按最坏情况 0.98 + 0.11 = 1.09 美元，超过上限应停。按平均 0.98 + 0.011 = 0.991 美元还有余量，可继续。硬上限应按最坏情况判。
  3. COMPLETED 表示验收全部通过，运行正常结束。BUDGET_EXHAUSTED 是资源耗尽，可以追加预算接着跑。
  4. 最可能是验收失败的报告没有写回对话，只记进了日志。该查两轮之间模型输入有没有变化，失败报告是否出现在消息里。

第 13 章 · 动作边界：策略即代码、审批与沙箱

  1. 提示词里的规则可以被模型影响和重新解释，外部文档也能提出目标。权限要留在可信运行时的代码里。两层之间只放指令层提议、策略层判定一个方向，反方向没有通道，否则模型或外部内容就能给自己加权限。
  2. 前三条不变，计划模式写仍拒绝，需审批仍是询问，读仍是允许。第四行越界写入从拒绝变成询问，审批可能把它放行。
  3. 无效审批是 57/60 = 95%。可以按风险分级批量批准低风险动作，用规则把能自动判定的动作移出审批，并在审批框写清动的文件或记录。
  4. 内容侧把工具输出标记为数据，不能当指令执行，并限制长度与拼接位置。策略侧让这个提议进入决策函数，由路径或网络白名单拦下。

第 14 章 · 五种工作流模式与委派

  1. 链式在每次交接处检查上一步输出。路由在选完路径后复核必填字段与判定依据。编排者在合并时验证最终结果，并约束子执行者。
  2. 两段链式输入 6,400 + 900 = 7,300，输出 1,000。按 2 与 6 美元每百万算，约 0.0146 + 0.006 = 0.021 美元。两个执行者并行输入 12,800，输出 1,000，约 0.0256 + 0.006 = 0.032 美元。
  3. 五件事是目标、起始版本、允许影响的范围、限制，以及返回格式。限制里要写轮次、时间与父级取消。
  4. 给两个执行者分开的工作区或分支，限制各自可改的文件。合并规则在派出前写好，由一个负责人统一集成并重跑测试。

第 15 章 · 持久状态、崩溃窗口与恢复对账

  1. 落在意图已经写盘、结果还没写盘之间。动作可能已经提交，日志里却没有结果记录。
  2. 逐条记日志是 200 × 0.2 = 40 毫秒。每 50 条批量一次是 4 × 0.2 = 0.8 毫秒，最坏窗口拉长到 50 个动作，约 50 毫秒。
  3. 预期改动已在文件里，记成功并继续，不重放。动作没生效，重放补丁再记结果。状态和意图对不上，停下来交人工。
  4. 因为动作已提交但结果记录丢失，恢复流程误判为未执行就重放了。除了查外部状态，还可以给动作加幂等键，让重复执行只生效一次。

第 16 章 · 可观测性与实验设计

  1. 三个边界分别记运行入口、动作执行与验收。运行入口记提议与版本，动作执行记动作标识、策略决策与结果，验收记用例、耗时与停止原因。停止原因要记，否则复盘分不清是取消、预算耗尽还是解析失败。
  2. 一轮四组是 4 × 200 × 0.15 = 120 美元。每组 3 个种子，总花费 120 × 3 = 360 美元。
  3. 平均提升是 (1.8 − 0.4 + 0.9) ÷ 3 ≈ 0.77 个百分点。三次之间相差 2.2 个百分点，波动和提升同量级，一次运行说明不了问题。
  4. 断言恢复流程判定状态对不对、预算有没有被重复扣、权限有没有被绕过。工具、存储与代码会变，旧注入点可能打不到真实路径，所以要定期回看并更新注入点，避免断言通过却没测到东西。

第 17 章 · 工具、技能与端到端评估

  1. 单轮执行准确率是 81/90 = 90%。端到端完成率是 81/100 = 81%。
  2. 提升是 231/300 − 195/300 = 77% − 65% = 12 个百分点。它只证明这套技能在这批任务上有效，不能证明换任务或换模型后仍有效。
  3. A 是 2.20 ÷ 0.40 = 5.50 美元。B 是 1.80 ÷ 0.30 = 6.00 美元。A 更便宜，虽然它每次尝试更贵。
  4. 只报一个分数，分不清是防住攻击还是把合法任务一起拒了。同时报两个数，才知道防护的代价。

第 18 章 · 自改进与评估器的不可编辑面

  1. 四步是选父版本、改一处、重新评估、记录决定。一次只改一处才能归因，分数涨跌都能对应到具体改动。
  2. 保留15个版本，其中1个是基线，非基线保留版本有14个，占全部实验的14/83 ≈ 16.9%。83 × 1.5 = 124.5个GPU小时，摊到每个非基线保留版本约8.9个GPU小时。仅凭保留数，无法推知有多少版本真正超过最初基线。
  3. 6 个百分点大于假设的 ±4 单次波动，但仍可能是 20 选 1 的选择偏差和 50 题小样本噪声。要重跑多个种子、用独立验证集、固定同一评分口径，再看提升是否稳定；此时既不能宣布有效，也不能宣布无效。
  4. 要问改进下一轮研究员的那件东西，本身有没有被这一轮改过。没有被改过，就只是一次性优化。

第 19 章 · Transformer 通识：从 token 到下一个词

  1. 绝对位置向量加到嵌入上后，后面的 Q、K、V 都由相加后的向量算出。位置会进入 Q 和 K，所以能影响打分，也能参与编码词序。它的局限是每个位置只有固定编号，训练没见过的长度没有可靠表示，相对距离要模型从绝对位置里间接学。RoPE 不加向量，而是在注意力里按位置旋转 Q 和 K，点积里直接带上相对位移。点积仍受内容影响，不保证随距离单调下降。
  2. 若 q、k 各维独立、均值 0、方差 1，点积的方差约等于头维，不缩放会让 softmax 被单个位置主导；除以 √d_k 把方差拉回 1，不改变谁最大。头维为 4 时，缩放前 softmax 约为 93.6%、4.7%、1.7%；除以 2 后约为 73.6%、16.4%、10.0%。
  3. 因果掩码挡住未来，防止训练时抄答案；多头提供多组子空间，让不同关系并行计算；归一化控制激活尺度；残差保留直通梯度。它们都不提供事实证据，也不保证输出正确。
  4. 嵌入 2048×128=262,144 个（约占 57.0%）。前馈 3×128×344=132,096 个（约占 28.7%），注意力 4×128²=65,536 个（约占 14.2%）。单看一层内部，前馈约是注意力的两倍，整个 1 层模型里嵌入最大，每多一层约增加 19.8 万个参数，不到两层就超过嵌入表。所以必须先说明比较的是层内还是全模型，才能说「谁是参数大头」。
  5. 分数矩阵按 T² 增长，长度翻倍涨四倍；键值缓存按 T 线性增长，长度翻倍涨一倍。FlashAttention 省的是完整 T×T 分数矩阵占的峰值显存，以及显存与片上缓存之间的读写次数；没省的是 T² 的乘加运算量，它也不改变注意力的数学结果。
  6. 要去掉整个编码器，以及解码器里读取编码器输出的交叉注意力子层，只保留带因果掩码的自注意力和前馈。原图的 post-norm、正余弦位置编码、ReLU 前馈是原论文的选择。现在常见做法多换成 pre-norm、RoPE、SwiGLU。

第 20 章 · 训练三阶段：预训练、SFT、偏好与 RL

  1. 预训练学文本分布，信号是下一个 token 的预测。监督微调学示范，信号是请求与答案对。偏好与强化学习学打分，信号是对比或奖励。
  2. 微调只学示范，没有标准答案时学不到哪种回答更好。偏好学习用打分替代标准答案，把行为调向更受偏好的那一侧。
  3. 奖励黑客是策略学会刷分，例如变啰嗦或迎合用户。验证器盲区是只查最终答案，过程错但答案对也能拿奖励。
  4. 两个矩阵各是 8×4096 与 4096×8，合计 65,536 个参数。原权重矩阵是 4096² = 16,777,216，适配器占 0.39%。

第 21 章 · 推理为什么贵：量化、缓存与注意力

  1. 单步解码只算一个 token，算力下界约 0.05 毫秒。权重仍要读一遍，搬运下界约 7.4 毫秒，时间由带宽决定。
  2. 公式是 2 乘层数、批大小、长度、头数、头宽与字节。它随层数、长度与并发线性增长。
  3. 多个查询头共享一组键值头，缓存缩到八分之一。解码受带宽限制，缓存变小直接减少显存读取，所以收益明显。
  4. 每 token 每请求是 2×32×32×128×2 = 524,288 字节，即 512 KiB。4096 上下文单请求是 2 GiB，8 并发共 16 GiB。

第 22 章 · 成本估算：FLOPs、显存与容量规划

  1. m 是 B×T，k 与 n 都是 d，一个投影是 2BTd²。三个 QKV 投影合计 6BTd²，T=16、d=128 时约 1.573 MFLOPs。
  2. 7×10⁹ × 2 = 14×10⁹ 字节，约 14 GB。70B 按同样换算需要 140 GB。
  3. 单次响应 2,000 输入加 500 输出约 0.009 美元。8 次调用按 3 万输入加 4 千输出约 0.10 美元，比值约 11 倍。原因是每次调用都重发历史与工具定义。
  4. 80 GB 减 14 GB 权重，剩 66 GB，即约 61.47 GiB。每个请求 2 GiB，61.47÷2≈30.7，理论上只能开 30 个；留运行时与碎片余量，教学示意按 28 个规划。8192 上下文每个 4 GiB 时，理论 15 个。
