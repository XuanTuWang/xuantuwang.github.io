一个 token 是怎么生成的

假设接口返回的账单写着：输入 1,024 词元（Token），输出 96 tokens。输入里你只写了一句十五个字的请求，其余是系统提示（System Prompt）、两个工具定义和五轮历史。模型回的那两句话，也被折算成了 96 个 token。字数与 token 数对不上，价格却按 token 收。要弄清这笔账，得先看清模型生成一个 token 时到底做了哪些事。

打个比方，模型读文字不像人逐字默读，更像把整段话拆成一块块标准拼图，再一块块往外拼。每一块拼图就是一个词元（Token）。

正式定义：词元（Token）是模型读写文本时使用的最小单位，可以是一个词、词的一部分、标点或空白。模型先把输入切成 token，逐个计算，再一次生成一个新的 token，直到停下。

速览

一次生成分五段：分词、查表与位置、注意力（Attention）、前馈、打分与采样。参数在一轮里固定，变化的只有前缀。前四段基本是确定性计算，最后一段才引入随机性。温度（Temperature）与 核采样（Nucleus Sampling） 决定从概率分布里怎么挑，终止由结束符、长度上限或外部规则判定。这五段的形状决定了成本：序列越长，注意力越贵，缓存越占显存（GPU Memory）。

文字先变成什么，模型才能计算

计算机保存文字时使用编码，模型处理文字时还会再分成自己的单位。这个单位叫 token。它可能是一整个常见词，也可能是词的一部分、一个标点或一段空白。具体怎么切，取决于分词器（tokenizer）。

可以把分词器理解为一套固定的拼片字典。分词器（tokenizer）把句子拆成字典里的拼片，再给每片编一个号；小模拿到的是这串编号。编号用来查字典里的条目。两个编号挨得近，它们对应的词也可能毫不相关。

嵌入（Embedding）表把编号换成一排学到的数字，供后续计算使用。模型查表后取出的这排数字叫向量（embedding vector）。你可以先把它当作一组可计算的特征；真实向量的各维通常没有人工规定的“颜色”“大小”等名称。

一次只选一个，为什么仍然能写长文

下面用假设的分词方式演示一次预测。假设“关”和“打”各占一个 token。给定“请把灯”，下一 token 为“关”的概率是 0.5，为“打”的概率是 0.3，其余候选合计 0.2。

模型在采样步骤选出一个 token，把它接在已有文本后面，再算下一个。前面选了“关”，后续候选就会与选了“打”时不同。长回答这样逐步生成；每一步都会利用可用的上下文（Context），经过多层计算。

同样的输入也可能生成不同续写。调低温度会让采样更集中于高分候选；调高温度会让候选分布更平缓。

停一下，想想：词表编号、嵌入向量、下一词概率分别做什么？它们依次负责标识单位、提供可计算特征、描述候选输出。

机制

五段流水线

一次推理可以写成五段：分词、表示、注意力、前馈、打分与采样。第一段决定输入长什么样，中间三段做计算，最后一段产出 token。

段落输入输出关键组件
分词一段文本token ID 序列分词器与合并表
表示token ID[B,T,d] 特征嵌入查表与位置编码
注意力特征矩阵带上下文的特征多头注意力与残差
前馈特征矩阵逐位置变换后的特征层归一化（LayerNorm）与前馈网络
打分与选择最后一个位置的向量下一个 token输出投影与采样

每段都有明确的产物。分词产出整数序列，表示段把它变成形状 [B,T,d] 的张量：B 是批大小，T 是序列长度，d 是每一维特征的宽度。注意力段让每个位置读到前面的内容，前馈段做逐位置变换，最后一段只取最后一个位置的向量打分。

如图 3.2 所示，五段里只有最后一段引入随机性。前面四段在相同模型、相同硬件、相同批处理、固定随机种子的条件下基本固定；浮点和并行计算仍可能带来细微差异，但主要随机来源在最后的采样。

图 3.2 与上表使用同一套名字：分词、表示、注意力、前馈、打分与选择。选出的词元接回已有文本，模型再据此计算下一个词元。

五段是逻辑划分；工程实现会把相邻算子融合成一个核函数，对外观察到的仍然是这五段的输入与输出。

分词：把文本变成整数

Token 是模型读写的最小单元，可以是一个词、一个词片段、一个空格，甚至一个字节。分词器给每个单元分配一个整数 ID，ID 本身不带语义。

主流做法是字节对编码（Byte Pair Encoding，BPE）。它统计相邻单元的出现频率，反复合并最高频的一对，把词表控制在约 5 万条。

例：「A kitten sleeps.」会被切成 A、kitten、sleeps 与句点四段。四段分别对应 8、214、67、3 四个 ID（编号为示意）。

回到开头那句十五个字的请求。按中文平均每字 1.5 个 token 算（教学假设；随分词器变化，较新的中文分词器常低于此），它自己约 23 个 token，剩下的一千个左右是系统提示、工具说明与历史。账单里最贵的部分，往往是用户看不见的那一段。

切法直接影响账单。假设（示意）一段 2,000 字的中文政策文档，切法 A 平均每字 1.5 个 token，得到 3,000 token。切法 B 平均每字 1.9 个 token，得到 3,800 token。两个助手每天各调用一万次，都把这段文档放进输入，输入价按每百万 2 美元算。

切法 A 每天是 3,000 × 10,000 = 30,000,000 token，合 60 美元。切法 B 是 38,000,000 token，合 76 美元。差出来的 16 美元，全部来自平均分词长度。

分词还决定模型在细节上的「视力」。同一个订单号 ORD-1002，有的分词器切成 ORD、-、1002 三段，有的把 1002 再拆成四个单独数字。数字被切碎时，模型数位比对的难度上升，账单也变长（推断）。

语言之间的差距同样明显。中文常用字三千多个，一个汉字在多数分词器里占 1 到 2 个 token。同一句意思换成英文写，token 数通常更少（推断）。

在宽度 d 不变、只扩大词表的条件下，切分粒度会变粗。同一段文本通常得到更少的 token，序列长度下降；但嵌入矩阵从 [5 万, d] 变成 [10 万, d]，输出层同倍增长，显存不一定省。要按词表、维度与序列长度一起算。

查表与位置

嵌入层做的是查表：用 token ID 去一个 [V,d] 的矩阵里取一行，V 是词表大小。查表主要是访存，通常不计入浮点运算；若实现做类型转换或量化（Quantization）反量化，仍可能有额外计算。代价落在参数与内存上。

用一个小模型举例：词表 2,048、宽度 128、序列长度 16。ID 序列 [1,16] 查表后变成 [1,16,128]。这张表本身的参数量（Parameter Count）是 2,048 × 128 = 262,144 个，半精度下每参数 2 字节，约 0.5 MiB。词表翻倍，这张表也跟着翻倍，与序列多长无关。

X=E[ids]∈RB×T×d,∣E∣=V×dX = E[\text{ids}] \in \mathbb{R}^{B \times T \times d}, \qquad |E| = V \times dX=E[ids]∈RB×T×d,∣E∣=V×d

E 是嵌入表，ids 是 [B,T] 的编号，X 是 [B,T,d] 的向量。|E| 是表的参数量，只由词表与宽度决定。

只查表不够，还要告诉模型位置。词序一变，语义就变。现代模型多在注意力内部注入位置。示例的小模型用旋转位置编码：按位置给查询和键分别旋转一个角度，位置信息写进点积里，不新增参数表。

它的边界在长度外推。训练（Training）时见过 8,192 个位置，推到 16,384 时角度组合是没见过的，注意力的分数会变得不可靠（推断）。

注意力与前馈

注意力让每个位置读到前面的信息：查询与键做点积，softmax 归一化（Normalization）（把一组分数换算成总和为 1 的概率），再对值加权求和。这一步的形状是 [B,T,d] 进、[B,T,d] 出。

成本有两块。投影矩阵在宽度上做乘法，宽度翻倍，参数涨四倍。宽度 128 时，查询、键、值、输出四个投影合计 4 × 128² = 65,536 个参数。

分数矩阵在长度上做乘法，长度翻倍，元素涨四倍：序列长度 16 时，一层一个头的分数矩阵有 16 × 16 = 256 个元素。长度换成 8,192，元素数是 8,192 × 8,192 = 67,108,864 个，是前者的 262,144 倍。长上下文里，后一块会成为主导。

前馈网络负责逐位置的变换。示例用 SwiGLU（一种带门控的前馈结构），宽度扩张比取 8/3，三个矩阵的参数量合计约 8d²；宽度 128 时约 131,072 个（第 19 章配置取 d_ff=344，实际为 132,096），比注意力投影还多一倍。短序列时，它反而是浮点运算最多的一块。

两块成本计的东西不同：一块数参数，一块数临时张量。长度 8,192 时，单头单层的分数矩阵按半精度算要 67,108,864 × 2 字节，约 128 MiB。朴素实现会把整块矩阵留在显存，多头与多层再乘上去，峰值很快见底。

FlashAttention 等分块实现不必保存完整的 T×T 分数矩阵。它逐块计算并更新归一化结果，但乘加次数仍随 T² 增长。逐词生成时，还需要保存随前缀长度增长的键值缓存（Key-Value Cache）。

从 logits 到 token

最后一步只取序列最后一个位置，经输出投影变成词表大小的 logits。logits 是未归一化的原始分数，可以取任意实数。

温度除在分数上，再过一遍 softmax。温度小于 1 分布更尖，大于 1 更平，取最高项的做法不受温度影响。拿三个候选、分数 2、1、0 算一遍。温度 0.5 时，分数变成 4、2、0，取指数得 54.60、7.39、1.00，总和 62.99，最高项占 86.7%。温度 2 时，分数变成 1、0.5、0，取指数得 2.72、1.65、1.00，总和 5.37，最高项降到 50.6%。

贪心直接取概率最高的 token稳定、机械

Top-p 的截断也能手算。假设四个候选的概率是 0.5、0.3、0.15、0.05，阈值取 0.8。前两项累积刚好 0.8，候选集只留这两项，重新归一化后是 0.625 与 0.375。阈值取 0.9，前三个候选累积到 0.95 才越过阈值，候选集变成三项。

采样出 token 后，它被追加到前缀，下一次生成重新走一遍五段。终止有三种：生成结束符、达到长度上限、外部规则判定完成。

成本与限制

自回归（autoregressive）意味着不能回头改：每生成一个 token，就把它接回输入，再生成下一个；已经发出的 token 会成为下一轮的输入，早期错误会被后续内容放大（推断）。一个具体的样子：模型先写出「订单已签收」，后面补的发货时间、签收人、快递单号都顺着这个前提编。要纠正，只能删掉整段重写。

采样带来不可复现。同一输入两次生成可能不同，评估（Evaluation）时必须固定温度与随机种子。温度设成 0 也有代价：贪心解码（Decoding）在长输出里容易陷入重复，同一句话连着出现三四次。

还有一个字符层面的失败。温度偏高时，模型把 ORD-1002 写成 ORD-1OO2，数字零被换成字母 O。这类错误在字符层面很像，正则校验能拦住；拦不住的是另一种，ORD-1002 被写成合法的 ORD-1003。

长度是成本的主因。注意力分数的数量随长度平方增长。键值缓存（KV cache）存下已经算过的键和值，其容量随长度线性增长。第 21 章会算出它们各自的成本。流式输出还带来一个隐性限制：用户已经在读前 20 个字时，这 20 个字收不回来，发现错了只能另发一条更正。

token 是计量单位；下一章把 token 放回窗口，算一次调用能装多少、该装什么。

自测

  1. 五段流水线中，哪一段引入随机性，为什么其他段没有？
  2. 词表从 5 万扩到 10 万，序列长度与显存各自怎么变？
  3. 为什么温度调高会让同一问题的两次回答不同？
  4. 用正文的数字重算：序列长度 8,192 时，一层一头的分数矩阵有多少元素？它是长度 16 时的多少倍？若宽度取 128，注意力四个投影的参数合计是多少？
