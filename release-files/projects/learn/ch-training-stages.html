训练三阶段：
预训练、SFT、偏好与 RL

给模型一句「把这封客服邮件转成工单」，它可能续写一段邮件，也可能给出格式正确的 JSON。同一个问题，模型表现差别很大，背后往往是训练（Training）分了不同阶段。

打个比方，这三段训练像培养一位新人。先广泛阅读打下语言底子，这是预训练；再照着范例学干活格式，这是监督微调（Supervised Fine-Tuning）；最后根据好坏反馈调整取舍，这是偏好与强化学习。

正式定义：训练（Training）是用数据调整模型参数（Model Parameters）的过程。常见主线分三段：预训练学文本规律，监督微讲学任务示范，偏好与强化学习按比较或评分调整输出。各段用的材料和学习信号不同，回答的问题也不同。

速览

预训练学习文本规律。监督微调（Supervised 微调（Fine-Tuning），SFT）学习示范。偏好与强化学习依据比较或评分调整输出。三段主线解决会不会、像不像、好不好三个问题，数据与学习信号各不相同。

中间训练和推理训练是这条主线的扩展，用的仍是同一种模型结构。越往后数据越贵、量越小，效果越依赖评估（Evaluation）。代价集中在预训练的算力，以及后两段的稳定性。

学会续写、学会回答、学会选择

模型的能力会在不同训练环节中形成。预训练让模型通过大量文本中的预测任务学习规律。监督微调给出任务和示范回答，教它按预期方式响应。偏好或奖励反馈再调整它倾向于产生的输出。

这个顺序是常见教学框架，实际训练配方可以交替、组合，也可以缺掉某一阶段。比较两种方法时，要问它改动的参数、使用的数据与反馈分别是什么。

同一个天气请求，三种不同练习

预训练时，模型可能看到“今天的天气是晴天”，练习预测后面的文字。它学到语言与知识中的规律；实时天气仍要靠外部接口。

监督示范可以教它在用户询问天气时，生成城市与单位都正确的工具请求。外部程序仍然负责查询。只学会一个合法格式，还不够理解所有城市、日期与单位组合，所以要用变化后的任务检查。

奖励反馈可以根据执行后的结果评分。比如请求能否被解析、单位是否符合要求、最终答案是否引用了真实返回。评分越贴近真正目标，反馈才越有用。错误奖励也会鼓励错误捷径。

读资料为什么不等于训练

把一份新政策放进输入，可以让固定参数的模型参考它回答。这改变的是本次材料。训练需要计算目标、误差与参数更新，之后的模型权重（Weights）才会变化。两者都可能改善表现，但更新时间、成本与影响范围不同。

小模读到新笔记后改了回答，依据来自这次输入。训练程序用一批样例更新模型参数，改变的则是参数。判断模型是否学会了新东西，要看去掉这份临时笔记后，变化是否仍然存在，并核对训练记录。

某次回复更符合用户偏好，可能只是输入里多了偏好记录。判断是否训练过，要检查参数有没有更新，并核对训练记录。

对照两列，先找变化发生在哪：左列更新输入材料，参数不动；右列通过训练更新参数。矩阵里的数只表示变化位置。

机制

先看预测词元的训练怎样进行

先看预训练和监督微调中常见的词元（Token）预测任务。假设“金”单独占一个词元，读到“香港是亚洲的”后，下一个目标词元可以是“金”。训练时为各位置准备后续词元这个目标，计算预测与目标的差距，再通过优化过程调整参数。这里介绍的是词元预测训练损失（Loss）；后面的偏好与奖励优化使用不同的学习信号。

训练时喂给模型的是真实的上一个 token；它自己刚生成的 token 不进入下一步。整段序列因此能并行算损失，代价是训练与推理的输入分布不完全一致。

训练显存（GPU Memory）要按状态算。每个参数要存权重、梯度（Gradient）、FP32 主权重与两个优化器动量，合计约 16 字节。举例：7×10⁹ 个参数乘 16 字节，约 112×10⁹ 字节，也就是 112 GB，还没算激活与通信缓冲。

Mtrain≈16N bytesM_{\text{train}} \approx 16N \text{ bytes}Mtrain​≈16N bytes

N 是参数量（Parameter Count），16 是每个参数的状态字节数。N=7×10⁹ 时，M 约为 112 GB。

图 20.2 画出本章的三段教学主线。每段使用的数据和目标有所不同：预训练主要消耗大规模计算，监督微调需要合适的示范，偏好或奖励优化还要付出采样与评估成本。具体配方可以交替、组合。

这套账只算模型状态。激活、通信与框架开销还要另加，实际占用会更高。

预训练只学分布

预训练的数据是配比出来的。网页提供广度，代码提供可执行模式，书籍提供长语篇，数学与教育文本提供解题过程。比例失衡，模型的能力分布就跟着偏。

规模决定代价。Llama 3.1 用约 15 万亿 token 训练 8B 模型，消耗约 146 万 H100 卡时。按 6ND 粗估，N=8B、D=15T，稠密计算约 7.2×10²³ 次浮点运算。

训练要盯两条曲线。训练与验证都下降是健康信号；验证损失在固定步数后回升，说明过拟合，应回滚到最佳检查点（Checkpoint）再决定是否继续。

失败案例：验证损失连续上升时继续加步数，模型在训练集上更熟，在留出集上更差。回滚、查学习率与数据重复，比继续训练有效。

预训练的边界是钱与数据。多数团队不需要从头训练，只需要在已有基座上做后两段。

五种方法改的东西不同

把训练方法排开看，每种方法改的是不同对象，供给的数据也不同。

方法改什么供给什么数据
上下文学习本次请求的行为指令与示例
预训练广泛文本分布大规模文本混合
中间训练领域或长上下文能力聚焦文本与保留混合
监督微调期望回答的样式请求与答案对
蒸馏教师的行为教师输出或分布

这张表覆盖「改参数」的四类方法：预训练、中间训练、SFT、蒸馏；上下文（Context）学习不动权重。它没有列偏好/RL 和推理训练，后者见后面的小节。区别还在学习信号和目标函数；模型结构通常不变。

中间训练是预训练与微调之间的一层。它用更高质量的教育与解题文本、领域文档和长上下文数据继续训练，同时保留一部分通用数据做回放。回放的作用是防止能力回退，评估要留独立留出集。

中间训练最容易出问题的地方是回退。目标领域变强，通用能力可能退步。没有保留混合与回退检查，收益会被抵消。

长上下文也是一项中间训练目标。序列拉长，位置处理与注意力（Attention）都要重新验证，短序列上的效果不能直接外推。

监督微调把能力变成行为

监督微调（Supervised Fine-Tuning，SFT）用请求与答案对继续训练。答案仍按 token 生成，只是数据从自然文本换成了示范。

数据要覆盖五类：任务指令、多轮对话、代码与解题、偏好与安全行为、语言与格式。任务指令教摘要、分类与转换；多轮对话教用历史、守角色。

代码与解题教可执行或已验证的答案。偏好与安全行为教语气、拒绝与不确定表达。语言与格式教目标用户与输出结构。

数据来源可以分几类：人工撰写、教师模型生成、任务专家编写，以及人工与合成的混合；最后一种是把人工与合成配在一起的组织方式。教师生成的样本便宜，会带教师的错误与模板重复。

失败案例：把损失算在提示位上。模型会去学「怎么复述问题」，推理时更容易跑偏（推断）。正确做法是只在回答 token 上累加损失，提示位掩码置零。

数据切分要按会话或模板分组。同一订单的改写样本如果跨进验证集，指标会虚高。

省钱的版本是低秩适配（Low-Rank Adaptation，LoRA）。它冻结原权重，只训练两个小矩阵。宽度 4096、秩取 8 时，两个小矩阵各是 8×4096 与 4096×8，合计 65,536 个参数。原权重矩阵是 4096²=16,777,216 个参数，适配器占 0.39%。

∣θLoRA∣=2rd,2rdd2=2rd|\theta_{\text{LoRA}}| = 2rd, \qquad \frac{2rd}{d^2} = \frac{2r}{d}∣θLoRA​∣=2rd,d22rd​=d2r​

r 是秩，d 是原矩阵宽度。代 r=8、d=4096，参数量是 65,536，占比 16/4096≈0.39%。

量化（Quantization）低秩适配（Quantized Low-Rank Adaptation，QLoRA）把基座换成 4-bit。适配器仍按低秩方式训练；在 QLoRA 的特定配置下（4-bit 基座、低秩适配、梯度检查点等），单张 48GB 卡可以微调 65B 模型。

微调的另一面是遗忘。以下是一组教学示意数字：任务准确率从 70% 升到 90%，合法 JSON 从 40% 升到 98%，通用问答却从 60% 跌到 52%。专精与回退要同时盯。

偏好学习把行为调成偏好

偏好学习用人类或模型的打分替代标准答案。三种做法的差别在反馈从哪来，以及更新时和谁比较。这里的策略指模型当前的行为分布。SFT 通常只给一个可接受答案；当多个答案都能接受、但好坏有差别时，才需要偏好学习来排序。

方法反馈来源学习方式
近端策略优化（Proximal Policy Optimization，PPO）奖励模型给新回答打分与旧策略比较，限制单次更新幅度
直接偏好优化（Direct Preference Optimization，DPO）存好的坏回答对从对比中直接学习
组相对策略优化（GRPO）同一问题多个回答各自打分组内相对比较后更新

规模感来自一份公开配方。监督微调、奖励建模与策略更新大致都在万级到数万级样本（Ouyang 等，2022；具体数字随版本与统计口径变化）。数据形态从示范换成了对比与自采样记录。

直接偏好优化用已有的成对比较构造损失，省掉在线采样与奖励模型训练。评论网络（critic）估计价值，帮助计算策略的更新方向；近端策略优化需要评论网络，直接偏好优化不用。

失败模式有两种。奖励黑客是策略学会刷分，例如变啰嗦或迎合用户。分布漂移（模型产出的回答跑到奖励模型没见过的区域）是策略产出的回答超出奖励模型的可靠范围。要同时监控留出偏好、事实性、安全性与 KL 散度。KL 散度衡量新旧策略的偏离程度。

还有一条不依赖人类偏好的路线：用可验证的奖励替代打分，例如数学答案对错、代码单测是否通过。组相对策略优化（Group Relative Policy Optimization，GRPO）是其中常用的一种。

GRPO 的做法是同一问题采样一组回答，按组内结果算相对优势。举例：正确答案是 19，采样 4 个回答，解析值分别是 29、19、19、15。奖励是 0、1、1、0，减去组均值 0.5 再除以标准差 0.5，优势是 -1、+1、+1、-1。

验证器（按规则自动判分的程序）也有盲区。精确匹配怕解析错误与等价形式；代码单测怕用例覆盖不全；格式检查会让格式对、内容错的答案过关；步骤反馈标注贵且不可靠。

推理训练把计算花在思考上

推理训练可以分三件事看：让模型写步骤、用可验证奖励训练、把大模型（Large Language Model）的行为压缩到小模型。它们经常一起出现，各自解决不同的问题。这里的推理指 reasoning（推导过程）；第 21 章的 推理（Inference） 指用模型计算输出。

思维链（Chain of Thought，CoT）让模型先写中间步骤再给结论。每个新步骤都成为下一段输入，上下文会随步骤变长，推理成本也跟着上去。

举例：比较 0.11 与 0.9。先把精度对齐成 11/100 与 90/100，再比较 90 大于 11，得到 0.9 更大。差是 0.79，最后验证 0.11+0.79=0.90。

多步推理还会增加 token 成本：步骤越长，账单越高。下面只算生成的 token，不算训练时的前向与反向计算。

推理训练的 token 账很直观。1 万条请求下，监督微调按每条 1024 个目标 token 算约 1024 万 token；强化学习每条采 8 个回答，约 8192 万 token，是前者的 8 倍。

DeepSeek-R1 的配方把几段串起来：冷启动微调、推理强化学习、再一轮微调、跨任务强化学习。几段训练可以反复迭代，不必一次走完。

同一问题采样多个完整解再取多数投票，是另一条提升路径。代价是成倍的推理算力。

蒸馏是另一条压缩路线。小模型学大模型的输出分布，温度（Temperature）控制分布的平陡。高温让分布更平，传递类别之间的关系；正确答案只是其中一部分。

推理训练的收益受题型限制。题目超出验证器覆盖范围，训练收益会迅速衰减。通用可靠性不随单个题型的准确率自动上涨。

成本与限制

预训练的成本把多数团队挡在门外。8B 模型就要 146 万卡时，按每卡时 2 美元粗算，一次预训练约 292 万美元。

偏好学习有刷分风险。奖励模型被策略摸透之后，分数会继续上涨，质量未必跟着涨。

监督微调会遗忘。任务指标上升时，要同时盯通用能力与安全行为。

评估不能只看损失：任务准确率与训练损失（Loss）是两条曲线，要一起看。评估本身的成本也在涨；每题都要跑完整流程，样本一多，评估账单可能接近甚至超过微调成本，具体要看任务长度和调用价格。数据污染是隐性成本：验证集里的样本如果与训练样本同源，指标会好看但没有意义。
